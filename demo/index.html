01 · the bar to beat

Baselines before the model — and the baseline won for a long time

A precision-recall number is meaningless without its base rate; a coin scores 0.3079 here. The honest adversary is a running per-user adoption rate computed from the listener's own prior first-encounters — no training, no look-ahead. It out-scored every ID embedding model.

02 · the terminal experiment

Does the sequence add anything over the rate? Only if items are content.

Hand the encoder the exact in-context rate as an input and measure the sequence's contribution — twice, two ways of combining it, on the same cohort. The head's residual form fixes the rate as a base it can only add to; the answer flips entirely on how items are represented.

The head is byte-identical across all four runs; only the encoder's item embedding changes. An ID table memorises the train period and its learned correction misfires under temporal drift. A shared content projection can't memorise per item — so the sequence carries taste signal the rate lacks. The representation, not the head, decides whether the sequence beats the rate.

04 · how we know it's real

The result survives an honest test

The project's value is the method. Two findings were retracted mid-stream when the evidence turned — that discipline is the point.

paired · user-bootstrap

Resample users, not rows

Encounters within a listener aren't independent. A win is a paired difference whose 95% interval clears zero — never two overlapping marginal bars.

no look-ahead

An encounter never sees its own future

The in-context rate is resolution-gated and unit-tested: a prior counts only once its horizon has closed. The baseline plays by the model's rules.

built to lose

An adjudication that could fail

The in-context rate was added specifically to test whether the encoder's cold-user "win" was real. It wasn't — the encoder lost, and the claim was withdrawn.

retracted

"Content is weak" was a method artifact

Raw cosine and an unstable residual hybrid, not content. Run as a learned projection, even coarse genre beats an ID table; learned audio beats genre.

05 · in progress

Can richer content raise the ceiling?

The best content model so far is learned audio (musicnn). Music4All maps to 100% of the cohort's 56,512 tracks by Spotify ID, unlocking lyrics and release-era as new content — orthogonal to audio.

Training now: a fused musicnn ⊕ lyrics ⊕ era content model (multilingual lyric embeddings for 51,494 tracks, PCA-balanced against audio) + the in-context rate.
Open question: does it beat content+in-context (0.4520), or is musicnn already capturing the signal? Predicted-vs-actual demo on real listeners lands with it.

06 · limitations, stated plainly

What this is not

Single seed, single split. Discovery-slice margins are small; the headline is robust, the fine grain less so.

Temporal drift is real. Adoption falls from a 0.37 train rate to 0.31 on test, miscalibrating every train-fitted prior — the reason the training-free rate is so strong.

Reduced config. 15k users, history length 100, to fit a 6 GB laptop GPU. A max_len sweep confirms the conclusions hold.

The model consumes the rate. This is "content adds over the rate," not "content alone beats it" — the rate stays a large component.

Not a deployment. Trained on 2005–2020 Last.fm scrobbles; a live import would be out-of-distribution and illustrative, not calibrated.
